# Моды по ядру и популярное в поиске дополнений — дизайн

Статус: утверждён 2026-11-13 (короткий дизайн, небольшое изменение).

## Зачем
Fabric ставят ради модов, но pechka называет первую подвкладку «Дополнений» по найденным файлам: на свежем
Fabric-сервере без модов она называется «Плагины (0)», хотя поиск там ищет моды. А поиск дополнений
открывается пустым — популярное видно только после Enter на пустой строке, и у плагинов половина этого
«популярного» случайная (Hangar без сортировки отдаёт свежие проекты по 1–400 скачиваний).

## Цели
1. Первая подвкладка называется по ядру сервера:
   - Fabric / Quilt / Forge / NeoForge → «Моды (N)» / "Mods (N)";
   - Paper / Purpur / Spigot / Folia → «Плагины (N)» / "Plugins (N)";
   - в папке есть и плагины, и моды (гибридные ядра) → «Плагины и моды (N)», как сейчас;
   - ванильное ядро → «Плагины (0)» и вместо списка строка «Ванильное ядро не поддерживает плагины и моды —
     только датапаки» / "The vanilla core supports no plugins or mods — only datapacks"; `i` там даёт тост
     с тем же текстом.
   Пустой список на моддовом ядре — «Модов нет · i — найти и установить» / "No mods · i to find and install".
2. Поиск (`i`) для плагинов, модов и датапаков сразу при открытии показывает 10 самых скачиваемых дополнений
   под ядро и версию сервера; `n` догружает следующие 10. Ввод запроса и Enter — поиск по совпадению, как сейчас
   (тоже страницами по 10).

## Не цели
- Отдельная подвкладка «Моды» рядом с «Плагинами» (на Fabric плагины не запускаются — она была бы пустой).
- Велосити и прочие прокси — поведение не меняется.
- Новые источники, кроме Modrinth и Hangar.

## Анти-цели
- Открытие поиска не должно зависать: популярное грузится в фоне, строка ввода сразу доступна, как сейчас.
- Определение ядра не должно читать диск на каждой отрисовке — только при перечитывании списка.

## Подход
Выбран один разумный путь: оба изменения ложатся на существующий код (`Platform::detect`, `ps::search` со
страницами и `n`). Отдельная подвкладка отвергнута (см. «Не цели»).

## Как устроено (решено)
- Ядро определяется при `refresh_plugins` (`Platform::detect` по папке и команде запуска; ваниль — через
  `core_update::detect_with`, `Core::Vanilla`) и хранится в `PluginsView`; подпись и пустое состояние берут его оттуда.
- Пустой запрос сортируется по скачиваниям: Modrinth `index=downloads`, Hangar `sort=-downloads`
  (проверено на живом API 2026-11-13: ViaBackwards, ViaVersion, Essentials, WorldEdit в топе).
  Непустой запрос — как сейчас (Modrinth `index=relevance`, Hangar без сортировки).
- Страница — 10 строк. **Моё решение:** у Paper/Purpur, где источников два, страница — 5 из Modrinth и 5 из Hangar
  вперемешку (M, H, M, H…), а не общий список по скачиваниям: у Modrinth числа на два порядка больше
  (VeinMiner ~100 млн против ViaVersion ~0,5 млн), и Hangar не попал бы в топ-10 вовсе.
  Если один источник кончился или недоступен, страница короче (без добора из другого — у каждого источника
  своё смещение, и добор сбил бы следующие страницы). `n` работает, пока хоть у одного источника есть ещё.
- Подсказка в окне поиска: «пустой запрос — популярное» → «сейчас — популярное; введите название и Enter».

## Оставлено исполнителю
- Точное место хранения ядра в `PluginsView` и имена полей.
